# Post-Simulation Automation Workflow

This guide shows a lightweight post-simulation automation path that starts from a `.vsim` script and can be followed up from the desktop app after the run completes.

Primary example:

- `examples/post_simulation_automation_demo.vsim`

## 1. Goal

The example is designed for a post-run workflow:

1. run a small deterministic simulation
2. emit analysis and reporting artifacts automatically
3. keep output files easy to inspect from scripting or from the desktop UI

The example intentionally stays small so it can be used as an automation template.

## 2. What the example emits

The script enables these export paths:

- `write_xyz = true` — static geometry output
- `write_xyzf = true` — trajectory / replay frames
- `write_analysis_json = true` — machine-readable analysis summary
- `write_metrics_tsv = true` — tabular metrics for automation or spreadsheets
- `write_report_md = true` — readable report output
- `write_events_json = true` — event log for post-run inspection

It also enables selected visual exports under `[export.visual]`:

- RDF figure
- energy trace figure

Output directory:

- `out/post_simulation_automation_demo`

## 3. Script-first workflow

Run the example from the scripting environment:

```text
vsper run examples/post_simulation_automation_demo.vsim
```

After the run, use the emitted files as a post-simulation automation set:

- inspect `.json` output in downstream tools
- load `.tsv` metrics into analysis notebooks or dashboards
- open `.xyzf` in the lightweight viewer for trajectory sampling
- read the markdown report for quick human review

## 4. Desktop-app workflow

The desktop path is also post-simulation oriented.

### Run from the desktop app

In the desktop Run VSIM panel:

1. browse to `examples/post_simulation_automation_demo.vsim`
2. keep or edit the auto-derived `.dynx` output path
3. launch the run

The panel runs the CLI with `.vsim` input and a `.dynx` emission target. This makes the workflow useful for post-run replay and artifact inspection.

### Inspect artifacts after completion

After the run completes, inspect the output directory artifacts generated by the script:

- `*.xyz` for static structure
- `*.xyzf` for replay frames
- `*.json` for analysis and events
- `*.tsv` for metrics
- `*.md` for the report

If the run was launched from the desktop flow, the `.dynx` archive can be used as the viewer/archive-side artifact for replay-oriented workflows.

## 5. Why this is a good automation template

This example is intended to be copied and adapted.

Use it when you want:

- a small post-processing pipeline
- deterministic scripted output
- machine-readable summaries plus human-readable reports
- artifacts that are easy to inspect in the lightweight viewer or desktop tooling

## 6. Adaptation ideas

Common follow-up changes:

- switch the molecule or material system
- increase `max_steps` for a richer trajectory
- enable more `[analysis.*]` sections
- enable more `[export.visual]` outputs
- change `output_dir` per automation batch
