§ 1

Summary

The bridge doc defines what the identity entropy layer should do. This document converts that into ten concrete implementation tasks with priorities, interface contracts, open decisions, and acceptance criteria. Tasks are grouped into three priority tiers. P0 tasks are blocking for v5.2.0. P1 tasks complete the feature. P2 tasks can defer to a follow-on milestone.

Full implementation stub is in vsim/identity_entropy.cpp (bridge doc §10). write(IERecord&) must call sync() before writing. Writer must not throw after close() is called. Buffer strategy to be confirmed per DEC-04. 		§5, §10 P0 Open

J, dataloss, recoverability have defined derivation rules. dataentropy, hidden_activity, and projection_loss require physics model input — see DEC-02. state_quota maps to $Q_n$ (active identity count at current scale). entropy_flux is the frame-delta of identity entropy. CR-06 Wire coalescence_gate() into the bonding/clustering event system.
When the gate fires, emit nonzero coalescence_loss and residual into the IERecord for that frame. Gate is read-only — it must not mutate particle state on fire. coalescence_residual() provides the scalar loss value. See DEC-05 for projection operator definition. 		§7, §10 P1 Open
CR-07 Implement FormationContext::formation_memory() and wire its result into IERecord.formation_memory each frame.
The heuristic in the bridge doc §10 scores six declared descriptors. A real implementation should degrade formation_memory over time as the system thermalizes — the heuristic is the starting floor, not the ceiling. Thermalization model is out of scope for P1; static heuristic is sufficient to unblock. 		§8, §10 P1 Open
CR-08 Add "identity_entropy" as a valid entry in [observe].track.
When present, the runtime should activate identity entropy tracking. If the entry is present but [outputs.identity_entropy] is absent or enabled = false, emit a validation warning (not a failure). 		§9 P1 Open
CR-09 Per-frame vs summary-only write modes, controlled by write_per_frame and write_summary flags.
write_per_frame = false + write_summary = true should produce a summary-only .ie file (no row data, just the # SUMMARY block). Both false is a no-op that still creates the file with just the header. Both true is the default full output. 		§5 P1 Open

The .ie file path should be registered with the viewer's overlay system so per-identity entropy values can be visualised per frame. Exact overlay API is viewer-team's call — this task is just the registration handoff from the export pipeline. Can ship without this; viewer overlay is not required for the output layer to be useful. 		§5 P2 Open

§ 3

Interface Contracts

These are constraints that implementation must not violate, regardless of how tasks are subdivided internally. They follow directly from the bridge doc's core principle.

Non-negotiable constraints
  • IC-01 Identity entropy variables (J, dataloss, all IERecord fields) must never be written back into mutable simulation state. They are derived output only.
  • IC-02 The coalescence_gate() function is read-only. A gate fire produces a sidecar record. It does not create, remove, or modify particles.
  • IC-03 Render state must not mutate truth state. The viewer overlay (CR-10) reads from the .ie file; it does not feed back into the simulation kernel.
  • IC-04 FormationContext is a runtime-only object. It must not be serialised into .dynx or any ground-truth particle record.
  • IC-05 IEWriter::write(IERecord&) must call sync() before writing. Callers must not pre-call sync() and assume the writer will skip it — double-sync is safe; missing sync is not.
  • IC-06 A missing or disabled [outputs.identity_entropy] block must not degrade simulation performance. The code path must be a no-op when disabled.
  • IC-07 J must be in the range [0.0, 1.0] at all times. Clamp on computation, not on write. Values outside range indicate a model error, not a writer error.
§ 4

Open Decisions

These must be resolved before the tasks that depend on them can land. Each decision is assigned to a responsible party. Unresolved decisions block indicated tasks.

Decisions required from the team
  • DEC-01
    Schema bracket: [outputs.identity_entropy] or [export.identity_entropy]? The bridge doc deliberately deferred this. Pick one and stick to it. Blocks CR-03. If the rest of the export system uses [export.*] sub-tables, consistency suggests folding in. If [outputs.*] is the new direction, keep it separate.
  • DEC-02
    How are dataentropy, hidden_activity, and projection_loss computed? These require a model of the projection operator from identity-space to observable state. The bridge doc defines the concept but not the formula. Until resolved, CR-05 emits 0.0 with flag bit 0x1 set. Blocks CR-05 (full), CR-06 (partial).
  • DEC-03
    lineage_depth tracking strategy: per-object chain or global lineage registry? Each object could carry its own depth counter (simple, cheap, no global state), or the runtime could maintain a lineage map keyed on identity ID (accurate for re-coalesced objects, more memory). Blocks CR-05 for lineage_depth population.
  • DEC-04
    IEWriter buffer strategy: stream per frame or accumulate N frames then flush? Streaming per frame is simpler and crash-safe. Buffering N frames is faster for large simulations with many identity-bearing objects. The summary pass already buffers all records in memory — if memory is a concern the summary could be computed as a running accumulator instead. Blocks CR-04 finalisation.
  • DEC-05
    Definition of the projection operator $\Pi_n$ for coalescence residual computation. coalescence_residual() takes cluster_state and projected_identity as caller-supplied vectors. Who computes the projection, and how? The bridge doc defines $R_{\text{coal}}^{(n)} = C_n - A_n(I^{\star}_{(n+1)})$ but the reconstruction operator $A_n$ is not yet specified. Blocks CR-06.
§ 5

Acceptance Criteria

A milestone is shippable when all P0 and P1 criteria below are checked off. P2 criteria are tracked but not required for v5.2.0.

AC-01 · CR-01 + CR-03 + CR-04 · P0 A surface deposition run with [outputs.identity_entropy] enabled = true produces a valid .ie file at the declared path.
AC-02 · CR-04 · P0 The .ie file contains a header row, at least one data row per frame, and a # SUMMARY block with rows, mean_J, min_J, and coal_events.
AC-03 · CR-05 · P1 J is within [0.0, 1.0] for all rows. dataloss equals 1 - J to within float64 tolerance. recoverability equals 1 - projection_loss.
AC-04 · CR-07 · P1 A run with all six formation descriptors declared produces formation_memory = 1.0 on frame 0. A run with no formation block produces formation_memory = 0.0.
AC-05 · CR-02 · P0 A run without a [formation] block executes successfully and the validation report contains a formation: incomplete warning. No hard failure is emitted.
AC-06 · CR-06 · P1 When a coalescence event fires, the corresponding frame row in the .ie file has coalescence_loss > 0.0. Frames without coalescence events have coalescence_loss = 0.0.
AC-07 · CR-03 · P0 [outputs.identity_entropy] enabled = false produces no .ie file and no measurable performance overhead versus a run without the block at all.
AC-08 · CR-08 · P1 A script with "identity_entropy" in [observe].track but no [outputs.identity_entropy] block emits a validation warning and runs without error.
AC-09 · CR-09 · P1 write_per_frame = false + write_summary = true produces a .ie file with only the header and # SUMMARY block — no data rows.
AC-10 · CR-10 · P2 With attach_to_viewer = true, the .ie file path is registered with the viewer overlay system. The viewer can display per-identity entropy values without the simulation re-running.
