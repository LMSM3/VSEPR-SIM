## Structure

### 1. Motivation

Physical interactions span scale tiers from sub-angstrom to macro-composite. No single force-field captures all
of them faithfully. This paper introduces a registry-based approach where each interaction family is treated as
an identifiable object with a fitted recovered length scale, state-dependent prior, and a quantified gap against
empirical reference data.

### 2. Scale Registry

Define scale tiers S1-S6. Each tier has a canonical range and a corresponding set of interaction families.
Introduce the recovered length scale Lambda_X as the e-folding distance of the recovery function A_X(L).

### 3. Interaction Families

Enumerate canonical families: pi_N, HB_N, vdW_N, disp_N, rep_N, sign_halo, sigma_hole, pi_hole,
metal_ligand, solvation, surface. Each family has a primary_scale tier and a casting type (field_field,
force_force, or mixed).

### 4. Field-Field vs. Force-Force Distinction

Field-field interactions propagate over extended spatial domains. Force-force interactions are pair-local.
The distinction governs which gap labels are valid and which next-run families are generated.

### 5. Recovery Length Definition

Asymmetry rule: above-ideal (L > Lambda_X) and below-ideal (L < Lambda_X) are physically distinct failure
modes and must not be penalised symmetrically.

### 6. EmpiricalDB Track

The external reference track. Sources: CSD, PDB, QM-derived datasets. Each record carries object_id,
family, state, length_prior_nm, length_sigma_nm, energy_prior, energy_sigma, dataset_source, confidence.

### 7. Simulation Track

Raw VSIM output normalized via vsim_output_filter into EmpiricalDB-compatible records. Canonical fields:
source_type=simulation, Lambda_nm, E_value, UFF, CFF, primary_scale, gap_label=pending, run_id.

### 9. Backmatter Tables

Final output: solved length-energy table with Lambda_solved_nm, E_solved, confidence_score,
gap_label, validation_status per object. These tables serve as the machine-readable backmatter
for the simulation validation pipeline.
